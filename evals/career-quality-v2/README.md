# Career-quality v2 — проверка смысла при правильных метаданных

Эта версия исправляет пять известных пропусков candidate-fit и проверяется на
новых ответах. Все исходные файлы и результаты v1 сохранены побайтно; их инвентарь
записан в [PREDECESSOR.json](PREDECESSOR.json). Инженерный benchmark Polaris,
установщик, `kit/` и releases не меняются. Всё работает на Python 3.9+ со
стандартной библиотекой, без API, установки зависимостей, commit или push.

**Результат:** пять известных ошибок исправлены, но на новых ответах остаются
21 пропуск и два ложных отказа. Из пяти отклонённых неправильных ответов один
отклонён по неверной причине. [Полный разбор v1 → v2](ANALYSIS.md).

## Что изменено

- [candidate.py](graders/candidate.py): количественные утверждения в выводах,
  заявленный масштаб, общее «полное соответствие» при неподтверждённых строках,
  давность опыта против будущей способности, принятие инструкций из JD.
- [preference.py](graders/preference.py): ограниченные проверки обоснований,
  выводов и next_step на выдуманные исключения/офферы, обход обязательных условий,
  расширение личного исключения, изменение частоты, авторитет по дате, перенос
  условий одной команды на другую и уверенность при отсутствии информации.
- Общий контракт и механические проверки сохранены. Набор допустимых меток и
  доказательств берётся из подготовленного gold; runtime не создаёт эталон сам.

`grade(packet)` остаётся чистой функцией; возвращает `pass`, `fail` или `invalid`,
список замечаний и `assurance: rule_checks_only`. `pass` означает отсутствие
обнаруженной ошибки, а не доказанное понимание всей прозы. Нет балла качества,
оценки человека или вероятности интервью. Подробный JSON-контракт совместим с
[v1](../career-quality-v1/GRADERS.md) и уточнён в [CONTRACT.md](CONTRACT.md).

## Новые данные

[cases/](cases/) содержит 13 синтетических сценариев и **52 новых ответа**:
5 candidate-fit × 4 ответа и 8 preference-fit × 4 ответа. Всего 26 предложенных
допустимых и 26 намеренно ошибочных ответов. [AUTHORING.md](AUTHORING.md)
содержит индекс ситуаций и сведения об авторстве.

Все ответы имеют полное покрытие, допустимые метки, буквальные цитаты из
достаточных наборов источников и разрешённые действия. У preference-fit поля
target/label/evidence/action одинаковы у всех четырёх вариантов в кейсе.
Плохой ответ отличается смыслом обоснования, вывода или следующего шага.
Допустимые варианты включают отрицания, ограниченный масштаб, условность и
корректные вопросы к работодателю.

Это предложенная агентами разметка. Она проверена другим агентом, но не
утверждена человеком. Ситуации выбраны специально для известных семейств ошибок;
это не репрезентативная выборка реальных карьерных советов.

## Разделение разработки и проверки

Автор правил видел старые кейсы и пять известных ошибок v1, но не новые кейсы
или их ответы. Автор новых кейсов не видел код и тесты v2. Рецензент сначала
проверил код на придуманных им примерах, затем — после фиксации кода — проверил
новые ответы и gold без запуска грейдера. Root ознакомился с новыми ответами
только после `CODE_FREEZE.json`.

Разделение процедурное: общая файловая система, модели и объявленные семейства
ошибок. Это нельзя выдавать за независимый blind holdout. Код первой версии v2
после результатов нового набора не подгоняется. Будущие исправления требуют
следующего сохранённого варианта, а не перезаписи этой проверки.

## Команды

Из корня репозитория:

```sh
python3 -B -m unittest discover -s evals/career-quality-v2/tests -v

# Фиксации уже созданы при подготовке; повтор не перезаписывает файлы.
python3 -B evals/career-quality-v2/pipeline.py freeze-code
python3 -B evals/career-quality-v2/pipeline.py audit-data
python3 -B evals/career-quality-v2/pipeline.py freeze-data

# Для повторного выполнения выберите НОВЫЕ output-папки.
python3 -B evals/career-quality-v2/pipeline.py run --suite new --engine v2 \
  --output evals/career-quality-v2/runs/new-v2
python3 -B evals/career-quality-v2/pipeline.py run --suite new --engine v1 \
  --output evals/career-quality-v2/runs/new-v1
python3 -B evals/career-quality-v2/pipeline.py run --suite regression --engine v2 \
  --output evals/career-quality-v2/runs/regression-v2

# Повторная проверка сохранённого результата без grading.
python3 -B evals/career-quality-v2/pipeline.py verify \
  --output evals/career-quality-v2/runs/new-v2
```

В новом сравнении v1 и v2 получают идентичные пакеты и их порядок. Старые 96
ответов составляют отдельный regression-набор; их нельзя суммировать с новыми
так, чтобы скрыть качество обобщения.

## Артефакты и повторное использование

`pipeline.py` создаёт отдельные фиксации кода и данных, а затем новый каталог
для каждого прогона. Пакеты лишены идентификаторов ответов, ожидаемых вердиктов
и описаний намеренных ошибок. Предсказания сохраняются перед сравнением с
аннотациями. Измерение и структурная проверка переиспользуют неизменённые функции
v1 через `legacy.py`; отдельные subprocess используют нужную версию грейдера.

Каждый прогон содержит пакеты, приватную для evaluator карту исходных ID,
результаты, метрики, читаемый отчёт и хеши. Здесь все данные синтетические;
карта не передаётся runtime. Python audit guard запрещает файловые, socket и
process операции во время `grade`; это не полноценная OS-песочница для
враждебного кода. Хеши подтверждают локальную связность, не внешнюю подпись.

Для будущей интеграции нужны `graders/` и адаптер к чистому JSON-интерфейсу.
Экспериментальный runner дополнительно зависит от сохранённых утилит v1.
Оценка реальных ответов требует рассмотренного gold и отдельной проверки
семантики; эта версия по-прежнему использует ограниченные английские шаблоны.
