# Saved two-rubric reviews

`review.py` saves **manual/agent judgments** from [jd-fit.md](jd-fit.md) and
[employer-fit.md](employer-fit.md). It does not grade an answer or infer fit.
Use it in a private candidate workspace with Python 3.9+:

```sh
python3 .maguire/kit/graders/review.py init \
  --assessment RESULT.md --cv inputs/CV.pdf --jd inputs/JD.txt \
  --output reviews/agent-001
# Optionally add --preferences inputs/preferences.md if that is a separate source.
# Apply both textual rubrics; edit both *.draft.json files.
python3 .maguire/kit/graders/review.py finalize \
  --bundle reviews/agent-001 --revised RESULT-revised.md
```

`init` creates a new bundle with `assessment.original`, `cv.source`,
`jd.source`, optional `preferences.source`, `manifest.json`, and two pending
drafts. Inputs are copied byte for byte. A later edit to the working
`RESULT.md` does not change the original. `--revised` is optional; when given,
`finalize` copies that separate answer to `assessment.revised`. It does not
replace the original or rebind the reviews to the revision.

Each draft has this shape (the `bindings` object is generated by `init`):

```json
{
  "schema": "maguire-fit-review.1",
  "rubric_id": "maguire-jd-fit.1",
  "bindings": {
    "assessment_sha256": "<generated SHA-256>",
    "cv_sha256": "<generated SHA-256>",
    "jd_sha256": "<generated SHA-256>",
    "preferences_sha256": null
  },
  "reviewer": "Reviewer name or agent identity",
  "method": "agent",
  "status": "reviewed",
  "summary": "The answer covers the prototype but leaves production ownership unresolved.",
  "coverage": ["requirement-1"],
  "findings": [{
    "id": "requirement-1",
    "verdict": "partial",
    "rationale": "A prototype does not establish production ownership.",
    "evidence": [
      {"source": "jd", "quote": "Build production services.", "locator": "line 1"},
      {"source": "cv", "quote": "Candidate built a prototype.", "locator": "line 1"}
    ],
    "answer_quote": "Candidate built a prototype."
  }],
  "needs_review_reason": ""
}
```

Use `maguire-employer-fit.1` in the employer draft. JD verdicts are
`supported`, `partial`, `unknown`, or `contradicted`; employer verdicts are
`aligned`, `conflict`, or `unknown`. The coverage IDs represent the material
requirements or supplied preferences inventoried under the relevant rubric.
Every `reviewed` coverage ID needs a finding. JD `supported`, `partial`, and
`contradicted` findings require both JD and CV evidence. Employer `aligned`
and `conflict` findings require both JD evidence and a candidate preference
quote from the CV or optional preference source. `unknown` may cite only the
available side, with a rationale naming the missing evidence or unresolved
reading. Add all material evidence needed to explain the judgment; a quote's
presence alone does not prove the verdict. `answer_quote` may be empty for an
omission; otherwise it must occur in the original answer. UTF-8 source quotes
must occur in their snapshot. For binary sources such as PDFs, supply a
nonempty page/section `locator`; the reviewer must verify the extracted quote.

`status` is `reviewed` when the rubric assessment was completed, regardless of
whether the findings are favorable. Use `needs_review` and a specific
`needs_review_reason` when evidence or interpretation remains unresolved.
If no candidate preferences were supplied, employer fit can retain empty
coverage and findings with `needs_review` and an explicit reason. Preferences
may also be present in a candidate-approved CV; the optional preference file
is not a semantic prerequisite. Allowed methods are `human`, `agent`, and
`human_and_agent`. Pending or placeholder drafts cannot be finalized.

`finalize` checks both drafts, exact rubric IDs and generated bindings, and
the copied input hashes before it creates separate `jd-fit.review.json`,
`employer-fit.review.json`, and `receipt.json`. Existing final files are never
overwritten, and failure does not create a success receipt. The receipt is a
local byte-identity record, **not** human approval, an independent seal, or
proof that an application was sent. Keep the bundle private; it contains the
CV, JD, answer, and possibly preferences.
